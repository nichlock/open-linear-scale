# Firmware

Firmware for the sensor PCB's STM32L476RC. It drives the emitter sequence, samples the analog frontend and streams measurements over UART. It is a [PlatformIO](https://platformio.org/) project using the STM32Cube HAL and LL drivers.

The position algorithm itself is explained in the [main README](../README.md#the-position-algorithm). This README expects that the algorithm is understood.

# Building and Flashing

Install PlatformIO (the VS Code extension or the CLI), then from this folder:

```sh
pio run -e release -t upload
```

Flashing uses a J-Link. I use a J-Link EDU Mini and a tag-connect TC2030-CTX. 

The build environments are defined in [`platformio.ini`](platformio.ini). `release` is the sensor firmware, and other environments are isolated tests of the software and hardware.

There is a major difference in timings with vs. without hardware floating point; [`scripts/sync_fpu_linkflags.py`](scripts/sync_fpu_linkflags.py) explains why the FPU flags need copying onto the link line.

The project uses PlatformIO's `nucleo_l476rg` board definition because it targets the same STM32L476 family. The sensor PCB doesn't use any Nucleo hardware. **Note that the board definition assumes the RG part's 1MB flash, while the sensor PCB has the 256KB RC part.**

# Architecture

The measurement runs almost entirely in hardware. The CPU only steps in once per sequence.

1. **TIM2** runs at 16 steps per sequence (16kHz by default).
2. On each timer update, **DMA1 channel 2** copies the next entry of the emitter state table into the GPIOC `BSRR` register, which switches all 8 emitters at once.
3. A TIM2 compare channel fires `TX_RX_DELAY_US` after each step and triggers **ADC1**. The ADC hardware-oversamples the selected input, using as many conversions as fit in about 90% of a step, rounded down to a power of two.
4. **DMA1 channel 1** collects the 16 oversampled values. When a sequence completes, its interrupt copies them to a shared buffer and increments a sequence counter.
5. The **main loop** waits for the next sequence, copies the readings out safely, combines them into lanes and handles the output.

The op-amps, DAC and timers that support this are initialized and commented at the top of `main()` in [`measure-main-events.cpp`](src/measure-main-events.cpp). The emitter pin map is `emitter_pins` in the same file, and `generateEmitterStateDataWrites()` builds the `BSRR` table from it when sampling starts.

All emitters are on one GPIO port by design, so one `BSRR` write switches them together. In the old method of reading the RX pad directly into an ADC, this was absolutely critical to keep the emitters aligned. With the charge integrator it has proven much less important, but I still keep single-port emitter arrays as a best practice.

# Sample Naming

The code uses specific names for its different sample types (conversion, oversample, sequence and transient). They are defined in the "Sample Naming Convention" comment in [`measure-main-events.cpp`](src/measure-main-events.cpp).

# Emitter States and Lanes

The emitter states are `emitter_states` in [`sensor-math.hpp`](src/sensor-math.hpp). Each entry is a bitmask of the 8 emitters, and the second half is the bitwise inverse of the first half. See [Combined Symmetric Measurements](../README.md#combined-symmetric-measurements) in the main README for why.

The main loop turns the 16 oversamples into `mapped_readings[4][2]`, two lanes of four transients. The comment above that mapping in [`measure-main-events.cpp`](src/measure-main-events.cpp) explains the cancellations.

`algo::evalPosition()` and `algo::updatePosition()` in [`sensor-math.cpp`](src/sensor-math.cpp) turn the lanes into a position. `updatePosition()` treats any jump of more than 3 (out of a period of 4) as a wrap, so the sensor must move less than a quarter of a period per sequence.

# UART Interface

The UART is USART3 on PC10 (TX) and PC11 (RX), at 460800 baud, 8N1.

I chose 460800 because it was the fastest I could get my cheap USB adapter to take data without dropping bytes.

## Commands

Commands are single lines ending in `\n` or `\r`. Numbers are parsed with `strtoul(..., 0)`, so they can be decimal or `0x` hex. A leading `0` makes a number octal, so `w 8 0500` writes 320, not 500.

| Command               | Action                                   | Reply                      |
| --------------------- | ---------------------------------------- | -------------------------- |
| `w <index> <value>`   | Write a register.                        | The written value in hex, or `ERR`. |
| `r <index> [count]`   | Read `count` registers starting at `index` (default 1). | Space-separated hex values, or `ERR`. |

## Registers

The registers are defined in `REGISTER_LIST` in [`measure-main-events.cpp`](src/measure-main-events.cpp), with their defaults and permission flags. A register's index is its position in that list, starting at 0. The values for the state, input, output and algorithm registers are the `StateMachine`, `ADC_INPUT_LIST`, `SampleOutputTypes` and `SensorAlgorithms` enums in the same file.

Permissions: `RD` = readable, `WP` = writable while stopped, `WR` = writable while running.

| Index | Name                          | Perms      | Description |
| ----- | ----------------------------- | ---------- | ----------- |
| 0     | `READING_F`                   | RD         | Latest tared position, as float bits. Units are set by `CONVERSION_FACTOR` (mm by default). |
| 1     | `ERROR_VALUE`                 | RD WP WR   | `ErrorFlag` bitfield. Write 0 to clear. See [Error Flags](#error-flags). |
| 2     | `SENSOR_STATE`                | RD WP WR   | `StateMachine` value. Write 0 to start, 1 to stop. |
| 3     | `CONVERSION_FACTOR`           | RD WP WR   | Float multiplier from sensor units to output units. Default 0.635 (mm). |
| 4     | `SENSOR_TARE`                 | RD WP WR   | Float, in output units. See [Tare](#tare). |
| 5     | `SENSOR_INPUT`                | RD WP      | ADC input, from `ADC_INPUT_LIST`. |
| 6     | `SENSOR_OUTPUT`               | RD WP      | UART output mode, from `SampleOutputTypes`. |
| 7     | `SENSOR_ALGORITHM`            | RD WP      | Emitter algorithm, from `SensorAlgorithms`. |
| 8     | `SEQUENCE_TIME_US`            | RD WP      | Length of one full emitter sequence, in µs. |
| 9     | `TX_RX_DELAY_US`              | RD WP      | Delay from emitter change to ADC conversion, in µs. |
| 10    | `CONVERSION_WINDOW`           | RD WP      | ADC sampling time setting (`LL_ADC_SAMPLINGTIME_*`). |
| 11    | `DISCARD_FIRST_SEQUENCE`      | RD WP      | Sequences to skip at the start of each burst printout. |
| 12    | `BURST_COUNT`                 | RD WP      | Sequences collected per burst in the burst output modes. |
| 13    | `BURST_OFFSET_ENABLE`         | RD WP      | In raw burst mode, capture the second half of the readings instead of the first. |
| 14    | `TRUE_OVERSAMPLE_CYCLE_NS`    | RD         | Achieved time per emitter state, in ns. |
| 15    | `TRUE_ADC_CONVERSION_NS`      | RD         | Achieved ADC conversion window, in ns. |
| 16    | `TRUE_ADC_DELAY_NS`           | RD         | Achieved TX-to-RX delay, in ns. |
| 17    | `SEQUENCE_TIMER_FREQ`         | RD         | Sequence timer clock, in Hz. |
| 18    | `TRUE_CONV_PER_OVERSAMPLE`    | RD         | ADC conversions per oversample. |
| 19    | `TRUE_ADC_OVERSAMPLE_TIME_NS` | RD         | Total ADC time per oversample, in ns. |

Registers with permission `P_WP` ("write-paused") and not `P_WR` ("write-running") can only be changed while the sensor is stopped. To change them, stop the sensor, write the registers, then start it again:

```
w 2 1      # SENSOR_STATE = stop
w 8 500    # SEQUENCE_TIME_US = 500
w 2 0      # SENSOR_STATE = start
```

The `TRUE_*` registers report what the hardware actually achieved after rounding the requested timing to the available timer and ADC settings.

### Tare

`READING_F` and the floating point UART output report the position minus the tare offset. Writing a float to `SENSOR_TARE` adds that value to the tare offset. The firmware consumes the value on the next measurement and resets `SENSOR_TARE` to 0, so each write applies once and repeated writes add up.

To zero the scale at its current position, write the current `READING_F` value into `SENSOR_TARE`:

```
r 0                # READING_F, e.g. 41200000 (10.0)
w 4 0x41200000     # SENSOR_TARE = 10.0, next readings are about 0
```

The offset is kept in sensor units, so changing `CONVERSION_FACTOR` afterwards does not move the zero point. You cannot read back the accumulated offset. To remove it, write its negative or reset the board.

## Error Flags

`ERROR_VALUE` is a bitfield of the `ErrorFlag` values in [`measure-main-events.cpp`](src/measure-main-events.cpp). New errors are also printed as `ERROR DETECTED: ...`. Writing 0 clears all flags, which might be set again if the erroneous condition is still present.

At the moment there is no way to mask errors, because errors are only placed where the code simply failed to function and could not proceed successfully anyway.

| Bit | Flag                          | Cause |
| --- | ----------------------------- | ----- |
| 0   | `ERRFLAG_BAD_CONFIG`          | Sampling could not start. Set together with one of the configuration flags below. |
| 1   | `ERRFLAG_BAD_SENSOR_INPUT`    | `SENSOR_INPUT` is not a valid `ADC_INPUT_LIST` value. |
| 2   | `ERRFLAG_BAD_SEQUENCE_TIMING` | The timing registers give an impossible timer, delay, conversion window or oversample ratio. |
| 4   | `ERRFLAG_UNKOWN_ALGO`         | `SENSOR_ALGORITHM` is not a valid `SensorAlgorithms` value. |
| 5   | `ERRFLAG_EMITTER_DMA`         | Transfer error on the emitter DMA channel. |
| 6   | `ERRFLAG_ADC_DMA`             | Transfer error on the ADC DMA channel. |
| 7   | `ERRFLAG_BURST_CONFIG`        | `BURST_COUNT` is larger than the burst buffer (2048). |
| 28  | `ERRFLAG_DROPPED_SEQUENCES`   | The main loop missed one or more sequences. |
| 29  | `ERRFLAG_TIMER_INTERRUPT`     | Reserved. Not raised by the current firmware. |
| 30  | `ERRFLAG_ADC_INTERRUPT`       | The ADC interrupt fired for an unknown reason. |
| 31  | `ERRFLAG_DMA_STACK_SMASH`     | The ADC DMA wrote past the end of its buffer. |

### Recovering From an Error

Any error stops sampling and sets `SENSOR_STATE` to `STATE_ERROR` (99). The UART still accepts commands, but no measurements are output until the sensor is restarted.

If the error came from a register setting (bits 0, 1, 2, 4 or 7), stop the sensor first, because the configuration registers can only be written while it is stopped. Then fix the setting, clear the flags and start it again:

```
r 1        # ERROR_VALUE, to see which flags are set
w 2 1      # SENSOR_STATE = stop
w 12 1024  # fix the bad setting, for example BURST_COUNT
w 1 0      # clear ERROR_VALUE
w 2 0      # SENSOR_STATE = start
```

For runtime errors (bits 5, 6, 28, 30 and 31), no settings need to change. Clear the flags with `w 1 0` and restart with `w 2 0`. If the same error keeps coming back, the problem is still present.

Clearing `ERROR_VALUE` alone does not restart the sensor. Writing `SENSOR_STATE = 0` alone restarts it but leaves the old flags set, so new errors with the same bits are not printed again.

A failure while initializing the clocks or peripherals at startup is fatal. The firmware stops responding to UART commands and blinks the status LED (D2, on PB13). Reset or power-cycle the board to recover.

## Output Format

`SENSOR_OUTPUT` selects what the firmware prints. It takes a `SampleOutputTypes` value:

| Value | Mode                    | Output |
| ----- | ----------------------- | ------ |
| 0     | `OUTPUT_FLOATING_TEXT`  | **Default.** One position per sequence (1kHz by default), as text with 6 decimals, for example `12.345678`. |
| 1     | `OUTPUT_FLOATING_HEX`   | One position per sequence, as the 8 hex digits of the IEEE-754 32-bit float, for example `41200000` for 10.0. |
| 2     | `OUTPUT_DBG_BURST_RAW`  | Raw oversamples, in bursts. See below. |
| 3     | `OUTPUT_DBG_BURST_DIFF` | Lane transients, in bursts. See below. |
| 4     | `OUTPUT_DBG_NONE`       | Nothing. The sensor keeps running and `READING_F` keeps updating. Useful for electrical measurements without UART activity. |

The position in modes 0 and 1 is the same value as `READING_F`: the tared position, scaled by `CONVERSION_FACTOR` (mm by default).

To change the mode, stop the sensor, write `SENSOR_OUTPUT` and start it again. For example, to switch to lane transient bursts:

```
w 2 1      # SENSOR_STATE = stop
w 6 3      # SENSOR_OUTPUT = OUTPUT_DBG_BURST_DIFF
w 2 0      # SENSOR_STATE = start
```

The setting is not saved. After a reset the firmware is back in text mode.

### Burst Modes

In the two burst output modes (raw and lane transients), the firmware collects `BURST_COUNT` sequences in RAM, pauses sampling, prints them and then resumes. Each burst looks like:

```
Sequence Rate: <timer ticks per sequence> ticks at <timer frequency> Hz
<index>,<l0_0>,<l0_1>,<l0_2>,<l0_3>,<l1_0>,<l1_1>,<l1_2>,<l1_3>,<sum>
...
end
```

In lane transient mode, the eight values are lane 0's four transients followed by lane 1's, and `<sum>` is their total. In raw mode, they are eight consecutive oversamples: the first eight of the sequence, or the last eight if `BURST_OFFSET_ENABLE` is set.

The first `DISCARD_FIRST_SEQUENCE` sequences of each burst are not printed, so the indices start at that value.

Sampling pauses while a burst prints, so there is a gap between bursts. The position keeps updating in the burst modes, but it is not reliable, because the sensor can move during the gap.
