# Firmware

Firmware for the sensor PCB's STM32L476RC. It drives the emitter sequence, samples the analog frontend and streams measurements over UART. It is a [PlatformIO](https://platformio.org/) project using the STM32Cube HAL and LL drivers.

The position algorithm itself is explained in the [main README](../README.md#the-position-algorithm). This README covers how the firmware implements it.

# Building and Flashing

Install PlatformIO (the VS Code extension or the CLI), then from this folder:

```sh
pio run -e release -t upload
```

Flashing uses a J-Link (`upload_protocol = jlink` in `platformio.ini`).

The project uses PlatformIO's `nucleo_l476rg` board definition because it targets the same STM32L476 family. The sensor PCB doesn't use any Nucleo hardware. Note that the board definition assumes the RG part's 1MB flash, while the sensor PCB has the 256KB RC part.

| Environment    | Purpose                                                                   |
| -------------- | ------------------------------------------------------------------------- |
| `release`      | The sensor firmware, built with the hardware FPU. This is the default.    |
| `bench_softfp` | Float vs. double timing benchmark (`test/benchmark-fpu-main.cpp`), software floating point. |
| `bench_hardfp` | The same benchmark with the hardware FPU.                                 |

`scripts/sync_fpu_linkflags.py` copies the FPU compiler flags onto the link line, so the linker picks the matching hard-float libraries.

# Architecture

The measurement runs almost entirely in hardware. The CPU only steps in once per sequence.

1. **TIM2** runs at 16 steps per sequence (16kHz by default).
2. On each timer update, **DMA1 channel 2** copies the next entry of the emitter state table into the GPIOC `BSRR` register, which switches all 8 emitters at once.
3. A TIM2 compare channel fires `TX_RX_DELAY_US` after each step and triggers **ADC1**. The ADC hardware-oversamples the filter output (or another selected input), using as many conversions as fit in about 90% of a step, rounded down to a power of two.
4. **DMA1 channel 1** collects the 16 oversampled values. When a sequence completes, its interrupt copies them to a shared buffer and increments a sequence counter.
5. The **main loop** waits for the next sequence, copies the readings out safely, combines them into lanes and handles the output.

Supporting peripherals:

- **OPAMP2** is the charge integrator, and **OPAMP1** is the anti-alias filter.
- **DAC1** provides the 1.65V bias (VREF) for the op-amps.
- **TIM5** is used to measure slack time.

The emitters are on GPIOC pins 13, 14, 15, 9, 8, 7, 6 and 2 (emitters 0–7, set by `emitter_pins`). All emitters are on one port by design, so one `BSRR` write switches them together. `generateEmitterStateDataWrites()` builds the `BSRR` table from the emitter states and this pin map when sampling starts.

If the main loop falls behind and misses a sequence, it reports `Missed sequences` and sets the `ERRFLAG_DROPPED_SEQUENCES` error flag.

# Sample Naming

There are several types of samples that run at different rates. For consistency, the code uses these definitions:

1. **Conversion**: An individual ADC sample/convert cycle.
2. **Oversample**: The value once the ADC's hardware oversample completes. There is one per emitter state.
3. **Sequence**: The full 16-state sequence, running at 1kHz by default.

A **transient** is not a sample. It represents the change between two consecutive oversamples, after the cancellations described below.

# Emitter States and Lanes

The emitter states are defined in `emitter_states` in `src/sensor-math.hpp`. Each entry is a bitmask of the 8 emitters:

```
0x0F, 0xE1, 0x1E, 0xC3, 0x3C, 0x87, 0x78, 0x0F,
0xF0, 0x1E, 0xE1, 0x3C, 0xC3, 0x78, 0x87, 0xF0
```

The second half is the bitwise inverse of the first half. The transitions alternate between flipping 6 emitters (three rising, three falling) and all 8 emitters (four rising, four falling).

![Emitter State Transitions](../docs/plots/emitter-state-transitions-diagonal.png)

The main loop turns the 16 oversamples into two lanes of four transients (`mapped_readings[4][2]` in `measure-main-events.cpp`):

- Each transient is the difference between consecutive oversamples, `readings[i] - readings[i-1]`. The first transient of a sequence uses the last oversample of the previous sequence.
- The transient from the second half of the sequence is the negative of the matching transient in the first half, so the two are subtracted to double the signal.
- **Lane 0** holds the 6-emitter transients (into states 1, 3, 5, 7).
- **Lane 1** holds the 8-emitter transients (into states 0, 2, 4, 6).

`casm::evalPosition()` in `src/sensor-math.cpp` finds the zero crossing in each lane and applies the half-step offset to lane 1, which gives two estimates within the period (0 to 4). The two estimates are averaged. `casm::updatePosition()` unwraps successive estimates into a continuous position. It treats any jump of more than 3 as a wrap, so the sensor must move less than a quarter of a period per sequence.

Both functions exist, but they are not called yet. On-sensor position output is not implemented, and the host scripts in [`tests/`](../tests/README.md) currently compute the position.

# UART Interface

The UART is USART3 on PC10 (TX) and PC11 (RX), at 460800 baud, 8N1.

## Commands

Commands are single lines ending in `\n` or `\r`. Numbers can be decimal or `0x` hex.

| Command               | Action                                   | Reply                      |
| --------------------- | ---------------------------------------- | -------------------------- |
| `w <index> <value>`   | Write a register.                        | The written value in hex, or `ERR`. |
| `r <index> [count]`   | Read `count` registers starting at `index` (default 1). | Space-separated hex values, or `ERR`. |

To change the sampling configuration, stop the sensor, write the configuration registers, then start it again:

```
w 2 1      # SENSOR_STATE = stop
w 7 500    # SEQUENCE_TIME_US = 500
w 2 0      # SENSOR_STATE = start
```

## Registers

| Index | Name                         | Default | Access | Description |
| ----- | ---------------------------- | ------- | ------ | ----------- |
| 0     | `READING_F`                  | 0       | Read   | Reserved for the position reading. |
| 1     | `ERROR_VALUE`                | 0       | Read/write | Error flags (see below). Can only be written to 0, which clears it. |
| 2     | `SENSOR_STATE`               | 0       | Read/write | Write 0 to start or 1 to stop. Reads 3 while running, 4 when stopped and 99 on an error. |
| 3     | `CONVERSION_FACTOR`          | 0       | Read/write | Reserved. |
| 4     | `SENSOR_INPUT`               | 3       | Config | ADC input: 0 = none (counter), 1 = DAC, 2 = integrator output, 3 = filter output. |
| 5     | `SENSOR_OUTPUT`              | 2       | Config | 0 = position (not implemented), 1 = raw oversamples, 2 = lane transients, 3 = no output. |
| 6     | `SENSOR_ALGORITHM`           | 0       | Config | 0 = the normal emitter sequence, 1 = drive individual emitters high then low (debug). |
| 7     | `SEQUENCE_TIME_US`           | 1000    | Config | Duration of one full sequence, in µs. |
| 8     | `TX_RX_DELAY_US`             | 38      | Config | Delay from an emitter step to the start of the ADC oversample, in µs. Must be shorter than one step. |
| 9     | `CONVERSION_WINDOW`          | 12.5 cycles | Config | ADC sampling time, as an STM32 LL `LL_ADC_SAMPLINGTIME_*` value. |
| 10    | `DISCARD_FIRST_SEQUENCE`     | 1       | Config | Skip the first sequence of each burst, while the ADC input settles. |
| 11    | `BURST_COUNT`                | 2048    | Config | Sequences per burst (maximum 2048). |
| 12    | `BURST_OFFSET_ENABLE`        | 0       | Config | In raw output mode, report the second half of the sequence instead of the first. |
| 13    | `TRUE_OVERSAMPLE_CYCLE_NS`   | —       | Read   | Actual time per emitter state. |
| 14    | `TRUE_ADC_CONVERSION_NS`     | —       | Read   | Actual time per ADC conversion. |
| 15    | `TRUE_ADC_DELAY_NS`          | —       | Read   | Actual TX-to-ADC delay. |
| 16    | `SEQUENCE_TIMER_FREQ`        | —       | Read   | TIM2 clock frequency, in Hz. |
| 17    | `TRUE_CONV_PER_OVERSAMPLE`   | —       | Read   | ADC conversions per oversample. |
| 18    | `TRUE_ADC_OVERSAMPLE_TIME_NS`| —       | Read   | Total ADC sampling time per oversample. |

"Config" registers can only be changed while the sensor is stopped. The "True" registers report what the hardware actually achieved after rounding the requested timing to the available timer and ADC settings.

## Output Format

In the two burst output modes (raw and lane transients), the firmware collects `BURST_COUNT` sequences in RAM, pauses sampling, prints them and then resumes. Each burst looks like:

```
Sequence Rate: <timer ticks per sequence> ticks at <timer frequency> Hz
<index>,<l0_0>,<l0_1>,<l0_2>,<l0_3>,<l1_0>,<l1_1>,<l1_2>,<l1_3>,<sum>
...
end
```

In lane transient mode, the eight values are lane 0's four transients followed by lane 1's, and `<sum>` is their total. In raw mode, they are eight consecutive oversamples.

Sampling pauses while a burst prints, so there is a gap between bursts.

## Error Flags

`ERROR_VALUE` is a bitfield. New errors are also printed as `ERROR DETECTED: ...`.

| Bit | Flag                         | Meaning |
| --- | ---------------------------- | ------- |
| 0   | `ERRFLAG_BAD_CONFIG`         | Invalid register configuration. |
| 1   | `ERRFLAG_BAD_SENSOR_INPUT`   | Invalid ADC input selection. |
| 2   | `ERRFLAG_BAD_SEQUENCE_TIMING`| The requested sequence time or ADC delay can't be achieved. |
| 4   | `ERRFLAG_UNKOWN_ALGO`        | Invalid `SENSOR_ALGORITHM`. |
| 5   | `ERRFLAG_EMITTER_DMA`        | DMA transfer error on the emitter channel. |
| 6   | `ERRFLAG_ADC_DMA`            | DMA transfer error on the ADC channel. |
| 28  | `ERRFLAG_DROPPED_SEQUENCES`  | The main loop missed one or more sequences. |
| 29  | `ERRFLAG_TIMER_INTERRUPT`    | Error in the timer interrupt. |
| 30  | `ERRFLAG_ADC_INTERRUPT`      | Unrecognized ADC interrupt. |
| 31  | `ERRFLAG_DMA_STACK_SMASH`    | The ADC DMA wrote past the end of its buffer. |

# Known Limitations

- On-sensor position output (`SENSOR_OUTPUT = 0`) and the `READING_F` register are not implemented yet.
- Only UART output is supported. SSI is planned.
